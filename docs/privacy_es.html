Política de privacidad

1. Procesamiento en el dispositivo e información que decides enviar

Mihiraki PDF Utility procesa archivos PDF en tu dispositivo. La aplicación no sube automáticamente contenidos de PDF, diagnósticos ni registros al desarrollador. Los PDF de origen, las copias de trabajo, los ajustes y los registros pueden almacenarse localmente para las funciones que utilizas.

Puedes optar por copiar diagnósticos, compartir registros con otra aplicación o enviar un informe de asistencia. La información que envíes puede ser recibida por el destino que selecciones y, en el caso de informes para este proyecto, por el desarrollador. Revisa el contenido y el destinatario antes de enviar.

2. Compras en la aplicación

Incluye compras opcionales procesadas de forma segura a través de Google Play.

3. Permisos

La aplicación utiliza los archivos que seleccionas para abrir, editar, guardar y exportar archivos PDF. Puede conservar una copia local del último PDF de origen abierto correctamente para volver a abrirlo tras reiniciar. Las ediciones no guardadas y el historial de Undo no se guardan automáticamente. Las descargas de muestras se conectan a GitHub, que gestiona los datos de conexión según sus propias políticas.

4. Cambios

Esta política de privacidad puede actualizarse periódicamente.

5. Registros locales y copias de asistencia

Los registros locales utilizan un umbral de limpieza de 24 horas. La limpieza se ejecuta cuando se ejecutan las funciones de registro pertinentes, utilizando las marcas de tiempo de las entradas o las horas de modificación de los archivos. No garantiza la eliminación de cada entrada exactamente 24 horas después de su creación, especialmente mientras la aplicación no se esté ejecutando.

La limpieza local no elimina los informes enviados, las copias exportadas ni las copias conservadas por otras aplicaciones, proveedores de servicios o copias de seguridad. Su retención y eliminación son independientes.

Para las copias de asistencia gestionadas por el desarrollador, el objetivo de eliminación es de 90 días después de que se cierre el caso. Las copias innecesarias se eliminan antes. Los casos abiertos y las excepciones limitadas se revisan semanalmente. Este objetivo no elimina automáticamente las incidencias públicas de GitHub Issues ni todas las copias externas o copias de seguridad.

6. Informes de asistencia y publicaciones públicas

Envía únicamente lo necesario para explicar el problema. La información de asistencia recibida por el desarrollador se utiliza para responder a la solicitud e investigar la incidencia. Los nombres, los identificadores de cuenta, el cuerpo de los mensajes y los archivos adjuntos no se copian de forma rutinaria en una hoja de seguimiento independiente. Cuando sea necesario realizar un seguimiento, conserva únicamente un identificador de caso, el enlace a la incidencia, las fechas, el estado y el registro de eliminación.

Las incidencias en GitHub Issues son públicas. La información del perfil, las publicaciones y los archivos adjuntos se gestionan conforme a las políticas de GitHub. Editar o eliminar tus propios comentarios es diferente de eliminar una incidencia completa, lo cual requiere al propietario del repositorio o a un administrador autorizado.

Para solicitar la eliminación de información en un informe destinado a este proyecto, contacta con el desarrollador a través del canal de asistencia original. No vuelvas a publicar información confidencial en una solicitud pública. Las publicaciones públicas, los registros de servicio, las memorias caché y las copias de seguridad tienen controles independientes; la aplicación no puede garantizar la eliminación de todas las copias.
