# サンプルPDF最新版一覧JSON対応（2026-11-19）

## 変更前

`SamplePdfCatalog`の固定51件と固定ReleaseのPDF URLだけを参照していた。過去の配布先変更記録はURL移行の検証であり、最新版一覧JSONの読込対応ではなかった。

## 実装

サンプル一覧画面を開くと、指定されたraw.githubusercontent.comの最新版JSONをIO上で取得する。ネットワーク待ちの間も前回一覧を読める。全件の文法・スキーマ・識別情報・URL・容量・SHA-256を検証後に、一時ファイルと同じファイルシステム内の原子的置換で前回正常一覧を更新する。失敗時は正常な前回一覧または同梱51件を維持し、不正な一覧を途中まで適用しない。

PDF URLは各entryの`new_download_url`を使い、GitHubの指定リポジトリ内の固定Release URLに限定する。latest/downloadへは変換しない。リダイレクトはHTTPSとGitHubの必要なホストだけを許可する。PDFのサイズ・ヘッダー・SHA-256確認は既存キャッシュ処理で継続する。

既存51件のID・言語・保存名を維持する。とくに`ep1_fil`と`ep2_fil`は配布URLの`_tl.pdf`と保存名の`_fil.pdf`を区別する。有効な旧一覧のスナップショットも保持し、後のJSONでハッシュが変わっても既存の検証済みPDFを優先して利用する。自動でPDFを削除・再取得しない。

## 検証と制限

- 公開最新版JSONと現行固定Release JSONをログインなしで取得し、entriesが51件で一致することを確認。
- 単体37件成功。新規8件では不正JSON（コメント・重複キー・過度なネスト含む）、未対応schema、重複ID、不正URL、通信失敗、一覧の再生成、旧ハッシュの取得済みPDF保持、通信待ち中のオフライン一覧参照を検証。
- Debug APK・実機テストAPKのビルド成功。Lintエラー0・既存警告11。
- Pixel 8aの別IDアプリで実通信によるJSONとFilipino第1話の取得・整合性検証に成功。ストア再生成後の擬似的な通信失敗でもキャッシュを再利用し、PDFの再取得がないことを確認。実際の機内モード検証とは区別する。
- 既存Play版・LOCAL版のAPKと端末設定は前後一致。一時アプリは削除済み。
